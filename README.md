# 🍃 Leaf on Rust

Порт ядра Leaf (форка Paper для Minecraft Java Edition **1.21.11**) на Rust. Цель проекта — перенести серверное поведение Leaf и сохранить совместимость с клиентами и плагинами.

[![Rust](https://img.shields.io/badge/Rust-000000?style=for-the-badge&logo=rust&logoColor=white)](https://www.rust-lang.org)
[![Minecraft](https://img.shields.io/badge/Minecraft-1.21.11-green?style=for-the-badge)](https://www.minecraft.net)
[![JVM](https://img.shields.io/badge/runtime-JVM%2025%20on%20Rust-orange?style=for-the-badge)](https://github.com/levin1337/java-25-on-rust)

Проект в разработке. `leaf-core` содержит Rust-компоненты ядра. `leaf-runner` запускает Java-сборку Leaf на [java-25-on-rust](https://github.com/levin1337/java-25-on-rust). `leaf-native` запускает локальный тестовый мир из Rust. Полный игровой цикл Leaf переносится отдельно.

## Структура репозитория

| Путь | Содержимое |
|---|---|
| [`crates/leaf-core`](crates/leaf-core) | Rust-порт серверных компонентов |
| [`crates/leaf-native`](crates/leaf-native) | Локальный Rust-сервер с тестовым плоским миром |
| [`crates/leaf-runner`](crates/leaf-runner) | Лаунчер Java-сборки Leaf для `jvm25-rust` |
| [`Cargo.toml`](Cargo.toml) и [`Cargo.lock`](Cargo.lock) | Rust workspace и зафиксированные зависимости |

`java-25-on-rust/`, Java-исходники и JAR-файлы Leaf, Gradle Wrapper и рабочая папка `run/` находятся вне отслеживаемых файлов этого репозитория. Java-дерево Leaf используется как референс для порта. Путь до него можно указать явно при запуске.

## Сборка и тесты Rust

Нужны Rust и Cargo. Команды запускаются из корня репозитория.

```bash
cargo build --locked -p leaf-runner
cargo test --workspace --locked
```

Для тестов Rust-компонентов достаточно этого checkout и зависимостей Cargo. При наличии зависимостей в локальном кэше добавьте `--offline`.

## Запуск тестового мира без JVM

Из корня репозитория запустите Rust-сервер.

```bash
cargo run --locked -p leaf-native
```

В Minecraft Java Edition **1.21.11** откройте «Сетевая игра» → «Прямое подключение» и введите `127.0.0.1:25565`. Если порт занят, запустите `cargo run --locked -p leaf-native -- --port 25566` и укажите `127.0.0.1:25566`. Остановка сервера через `Ctrl+C`.

По умолчанию нативный сервер создаёт обычный Верхний мир с холмами, реками, океанами, биомами, деревьями, пещерами и рудами. Новый игрок начинает в выживании на сложности Normal. Этот генератор использует шумовые функции Rust-порта; размещение рельефа и контента по seed отличается от ванильного Minecraft. Сервер подгружает до 32 чанков от игрока, отправляя ближайшие первыми. Чтобы использовать всю дальность, выставьте в клиенте прорисовку 32 чанка. Изменённые чанки автоматически сохраняются каждые 5 секунд в регионы Anvil `native-region/` внутри каталога мира. Оператор может записать их на диск командой `/save-all flush`, например перед остановкой сервера. После запуска блоки загружаются из этих регионов. Игроки в загруженных чанках видят общие изменения блоков и выпавшие предметы. В выживании из блоков выпадают предметы при включённом `block_drops`. В творческом режиме разрушенный блок не создаёт дроп. Сервер слушает только `127.0.0.1` и допускает вход без проверки аккаунта.

В инвентаре доступна сетка 2×2, а верстак открывает 3×3. Книга рецептов умеет раскладывать ингредиенты из инвентаря. После закрытия окна ингредиенты и предмет с курсора возвращаются в инвентарь. Если места нет, остаток выпадает рядом с игроком. В сетках работают ванильные рецепты 1.21.11, включая фейерверки, копирование книг и увеличение карт. Плавка, зельеварение и интерфейсы кузнечных станций относятся к отдельным механикам.

Новый каталог мира получает `ops.txt` с оператором `h0td04ek`. Операторы могут переключать режим клавишами **F3+F4**, выполнять `/gamemode survival [игрок]`, `/op ник`, `/deop ник`, `/time`, `/weather`, `/difficulty`, `/seed` и `/gamerule`. Чат, `/help` и `/kit` доступны всем игрокам.

По умолчанию сервер хранит данные игроков в `native-overworld/playerdata/`. Вход с тем же ником возвращает инвентарь, экипировку, активный слот хотбара и точные координаты с поворотом камеры, а также игровой режим и здоровье. Сохранение выполняется при выходе и автоматически каждые пять секунд. Для отдельного набора сохранений можно указать `--data-dir PATH` после `--` в команде Cargo. Задать seed нового мира можно через `--seed 322`. При первом запуске тип генератора и seed записываются в `world-generation`. Для плоского мира используйте `--world-type flat`. Прежние плоские миры можно открыть через их исходный `--data-dir`.

Для полёта введите `/kit`, чтобы получить элитры и ракеты. Поднимитесь, начните падать, один раз нажмите пробел для планирования и используйте ракету правой кнопкой мыши.

В загруженных чанках другие игроки видны с их экипировкой и движениями. Для ближнего PvP оператор может переключить обоих игроков командами `/gamemode survival` и `/gamemode survival ник`. В тестовом PvP работают удары рукой и мечом, отбрасывание, смерть и возрождение на спавне. Инвентарь сохраняется при смерти.

Мобы появляются группами на поверхности вокруг игроков. Ночью при сложности выше мирной появляются и враждебные мобы. Яйцо призыва можно использовать на блоке. Оператор может вызвать моба командой `/summon minecraft:pig` или задать координаты и количество. Для проверки массового спавна используйте `/summon minecraft:pig ~ ~ ~ 50000`. Сервер расставляет их вокруг указанной точки партиями по 256 за тик. Клиенту отправляются все мобы из загруженных для него чанков, включая границу в 32 чанка. Для отрисовки дальних мобов увеличьте дальность отображения сущностей в настройках Minecraft.

TNT поджигается огнивом, огненным зарядом или соседним источником питания (рычагом, красным факелом или блоком редстоуна). Взрыв меняет блоки у обоих клиентов, наносит урон рядом и поджигает соседний TNT. Действуют правила `tnt_explodes` и `tnt_explosion_drop_decay`.

Оператор может поставить 1000 блоков TNT одной командой `/fill ~1 ~ ~1 ~10 ~9 ~10 minecraft:tnt`. `/fill` принимает ID блока с его состоянием по умолчанию. Доступны `replace [блок]`, `keep`, `outline`, `hollow`, `destroy`. Размер области ограничивает правило `max_block_modifications` (32 768 блоков по умолчанию).

Операторская команда `/tick query` показывает состояние мира, целевой TPS, среднее время тика и перцентили P50, P95 и P99 по последним 100 замерам. `/tick rate 40` задаёт 40 тиков в секунду, `/tick freeze` ставит мир на паузу, а `/tick unfreeze` снимает её. `/tick step 20t` продвигает замороженный мир на 20 тиков, `/tick sprint 5s` ускоренно выполняет 100 тиков. Прервать эти режимы можно через `/tick step stop` и `/tick sprint stop`. На паузе доступны движение игроков и чат, а движение мобов и выпавших предметов, течение игрового времени и запалы TNT останавливаются.

Нативный сервер распределяет расчёты движения мобов, выпавших предметов и лучей взрыва между доступными ядрами. Потоки читают один снимок блоков, а игровой поток применяет результаты в заданном порядке. Подключения параллельно готовят обновления сущностей и кодируют изменённые чанки. Малые партии рассчитываются в игровом потоке. Чтобы запустить симуляцию на одном потоке, используйте `cargo run --locked -p leaf-native -- --worker-threads 1`.

## Запуск Java-сборки Leaf на Rust-JVM

Для запуска подготовьте бинарник `jvm25-rust`, образ `lib/modules` из JDK 25 и собранный bundler JAR Leaf 1.21.11. При размещении клона Rust-JVM в `java-25-on-rust/` сборка из корня выглядит так.

```bash
cargo build --release --manifest-path java-25-on-rust/Cargo.toml
cargo build --locked -p leaf-runner
```

Bundler собирается командой `./gradlew :leaf-server:createMojmapBundlerJar` в Java checkout Leaf с применёнными патчами. Для подготовки Java checkout используется `./gradlew applyAllPatches`. В PowerShell используйте `./gradlew.bat`. Локальные особенности сборки JVM описаны в [`AGENTS.md`](AGENTS.md).

### Запуск из рабочей папки

#### Bash

```bash
mkdir -p run
cd run
../target/debug/leaf-runner -- nogui
```

#### PowerShell

```powershell
New-Item -ItemType Directory -Force run | Out-Null
Set-Location run
& '../target/debug/leaf-runner.exe' -- nogui
```

| Что | Как находит лаунчер |
|---|---|
| `jvm25-rust` | `--jvm`, затем `JVM25_RUST`, затем `java-25-on-rust/target/release/` или `target/debug/` внутри клона JVM |
| `lib/modules` | `--modules`, затем `--java-home`, `JAVA_HOME` или `java -XshowSettings:properties -version` |
| Leaf JAR | `--jar` или новейший подходящий файл в `leaf-server/build/libs/` локального checkout. Автопоиск пропускает обычный `leaf-server-*.jar`, исходники и Javadoc |

Для JAR из другого checkout передайте абсолютный путь через `--jar`. Аргументы после `--` получает сервер.

### Dev-режим

Подготовьте в Java checkout файл с полным runtime classpath. Формат файла — одна строка с путями, разделёнными `;` в Windows или `:` в Linux и macOS. Пример для PowerShell из папки `run/`.

```powershell
& '../target/debug/leaf-runner.exe' --cp '@../leaf-server/build/runtime-classpath.txt' --main org.bukkit.craftbukkit.Main -- nogui
```

`--cp` и `--main` используются вместе. Для запуска через `--jar` используются параметры JAR-режима.

3. **Сущности и игроки** — подключить менеджер сущностей, конкретные сущности и AI, инвентарь игрока и игровые взаимодействия.
4. **Команды** — перенести оставшиеся аргументы, включая селекторы сущностей, и встроенные команды. Связать выполнение и подсказки с источником команд `ServerLevel` и игровой сессией.
5. **Data components** — загрузить каталог ванильных предметов с их прототипами, довести игровые модели, persistent-кодеки и разрешение именованных наборов holder.
6. **Plugin API** — перенести Bukkit/Paper API и проверить совместимость с плагинами. Rust-модуль `plugin` пока пуст.
7. **Нативные методы JVM** — внешняя зависимость проекта. В локальных логах зафиксированы файловые исключения при запуске.
8. **Полный прогон** — подтвердить запуск `nogui` до `Done` и подключение клиента на Rust-JVM.

### 🏃 Текущий запуск

`leaf-native` поднимает локальный TCP-сервер с обычным или плоским миром. Вход и загрузка мира проверены обычным клиентом Minecraft 1.21.11. TCP-тесты проверяют подгрузку чанков, спавн и сложность Normal в обычном мире, чат, команды и права оператора, полёт с ракетой, синхронизацию блоков и дропа между клиентами, а также крафт и возврат ингредиентов при закрытии окна или выходе. Дополнительные тесты проверяют естественный спавн, яйца, права на `/summon`, заливку 1000 блоков TNT у двух клиентов, очередь и отправку 50 000 свиней, видимость мобов на границе 32 чанков, цепной взрыв TNT и работу `/tick` с запалом.

`leaf-runner` запускает Java-сборку Leaf на Rust-JVM. В предыдущих локальных прогонах сервер доходил до `PaperBootstrap` и инициализации конфигурации Paper. В dev-режиме зафиксирована ошибка `Invalid TypeToken; must specify type parameters`. Запуск до `Done` пока не подтверждён.

## Участие в разработке

Сверяйте поведение Rust-кода с Java-референсом Leaf 1.21.11. Для изменений форматов и алгоритмов добавляйте целевые проверки. Перед Pull Request запустите тесты Rust workspace и обновите затронутые статусы в README. Деревья Java и Rust-JVM, сборки и рабочие данные остаются локальными.
