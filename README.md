# 🍃 Leaf on Rust

Порт ядра Leaf (форка Paper для Minecraft Java Edition **1.21.11**) на Rust. Цель проекта — перенести серверное поведение Leaf и сохранить совместимость с клиентами и плагинами.

[![Rust](https://img.shields.io/badge/Rust-000000?style=for-the-badge&logo=rust&logoColor=white)](https://www.rust-lang.org)
[![Minecraft](https://img.shields.io/badge/Minecraft-1.21.11-green?style=for-the-badge)](https://www.minecraft.net)
[![JVM](https://img.shields.io/badge/runtime-JVM%2025%20on%20Rust-orange?style=for-the-badge)](https://github.com/levin1337/java-25-on-rust)

Проект в разработке. `leaf-core` содержит Rust-компоненты ядра. `leaf-runner` запускает Java-сборку Leaf на [java-25-on-rust](https://github.com/levin1337/java-25-on-rust). `leaf-native` запускает локальный тестовый мир из Rust. Полный игровой цикл Leaf переносится отдельно.

## Структура репозитория

| Путь | Содержимое |
|---|---|
| [`crates/leaf-core`](crates/leaf-core) | Rust-порт серверных компонентов |
| [`crates/leaf-native`](crates/leaf-native) | Локальный Rust-сервер с тестовым плоским миром |
| [`crates/leaf-runner`](crates/leaf-runner) | Лаунчер Java-сборки Leaf для `jvm25-rust` |
| [`Cargo.toml`](Cargo.toml) и [`Cargo.lock`](Cargo.lock) | Rust workspace и зафиксированные зависимости |

`java-25-on-rust/`, Java-исходники и JAR-файлы Leaf, Gradle Wrapper и рабочая папка `run/` находятся вне отслеживаемых файлов этого репозитория. Java-дерево Leaf используется как референс для порта. Путь до него можно указать явно при запуске.

## Сборка и тесты Rust

Нужны Rust и Cargo. Команды запускаются из корня репозитория.

```bash
cargo build --locked -p leaf-runner
cargo test --workspace --locked
```

Для тестов Rust-компонентов достаточно этого checkout и зависимостей Cargo. При наличии зависимостей в локальном кэше добавьте `--offline`.

## Запуск тестового мира без JVM

Из корня репозитория запустите Rust-сервер.

```bash
cargo run --locked -p leaf-native
```

В Minecraft Java Edition **1.21.11** откройте «Сетевая игра» → «Прямое подключение» и введите `127.0.0.1:25565`. Если порт занят, запустите `cargo run --locked -p leaf-native -- --port 25566` и укажите `127.0.0.1:25566`. Остановка сервера через `Ctrl+C`.

В этом режиме доступен плоский мир из камня с перемещением и подгрузкой чанков. Мир существует в памяти и создаётся заново при каждом запуске. Инвентарь, изменение блоков, сущности и плагины относятся к полноценному игровому циклу. Для сборки нужны Rust и Cargo. Данные для входа берутся из встроенного пакета клиента 1.21.11. Сервер слушает только `127.0.0.1` и допускает вход без проверки аккаунта.

## Запуск Java-сборки Leaf на Rust-JVM

Для запуска подготовьте бинарник `jvm25-rust`, образ `lib/modules` из JDK 25 и собранный bundler JAR Leaf 1.21.11. При размещении клона Rust-JVM в `java-25-on-rust/` сборка из корня выглядит так.

```bash
cargo build --release --manifest-path java-25-on-rust/Cargo.toml
cargo build --locked -p leaf-runner
```

Bundler собирается командой `./gradlew :leaf-server:createMojmapBundlerJar` в Java checkout Leaf с применёнными патчами. Для подготовки Java checkout используется `./gradlew applyAllPatches`. В PowerShell используйте `./gradlew.bat`. Локальные особенности сборки JVM описаны в [`AGENTS.md`](AGENTS.md).

### Запуск из рабочей папки

#### Bash

```bash
mkdir -p run
cd run
../target/debug/leaf-runner -- nogui
```

#### PowerShell

```powershell
New-Item -ItemType Directory -Force run | Out-Null
Set-Location run
& '../target/debug/leaf-runner.exe' -- nogui
```

| Что | Как находит лаунчер |
|---|---|
| `jvm25-rust` | `--jvm`, затем `JVM25_RUST`, затем `java-25-on-rust/target/release/` или `target/debug/` внутри клона JVM |
| `lib/modules` | `--modules`, затем `--java-home`, `JAVA_HOME` или `java -XshowSettings:properties -version` |
| Leaf JAR | `--jar` или новейший подходящий файл в `leaf-server/build/libs/` локального checkout. Автопоиск пропускает обычный `leaf-server-*.jar`, исходники и Javadoc |

Для JAR из другого checkout передайте абсолютный путь через `--jar`. Аргументы после `--` получает сервер.

### Dev-режим

Подготовьте в Java checkout файл с полным runtime classpath. Формат файла — одна строка с путями, разделёнными `;` в Windows или `:` в Linux и macOS. Пример для PowerShell из папки `run/`.

```powershell
& '../target/debug/leaf-runner.exe' --cp '@../leaf-server/build/runtime-classpath.txt' --main org.bukkit.craftbukkit.Main -- nogui
```

`--cp` и `--main` используются вместе. Для запуска через `--jar` используются параметры JAR-режима.

## 📈 Статус разработки

Актуально на 2026-11-22. `cargo test --workspace --locked --offline` прошёл **154 теста** (150 в `leaf-core`, 2 в `leaf-native` и 2 в `leaf-runner`). Один doctest помечен как пропущенный.

### ✅ Работает и проверено тестами

| Подсистема | Что проверено |
|---|---|
| **NBT и SNBT** | Бинарное чтение и запись, GZIP, MUTF-8, ограничение чтения NBT, разнотипные списки в формате Leaf 1.21.11 и round-trip через SNBT. |
| **RNG** | Последовательности и операции `LegacyRandomSource`, `SingleThreadedRandomSource` и `XoroshiroRandomSource` сверяются с эталонными значениями. |
| **Позиции и математика** | Упаковка и преобразования `BlockPos`, `SectionPos`, `QuartPos` и `ChunkPos`, операции матриц и кватернионов JOML. |
| **Сетевые форматы** | Кодирование VarInt, VarLong и UTF-8, отдельные пакетные форматы и сериализация дерева команд. Проверена регистрация сетевых кодеков всех 104 встроенных data components. |
| **Anvil и палитры** | Чтение регионов `.mca` и внешних `.mcc` с GZIP, Zlib, LZ4 и без сжатия. Запись внутренних и внешних чанков сохраняет соседние записи. Секции, палитры блоков и биомов и карты высот проходят round-trip. Проверены восстановление повреждённых карт и поиск блоков ниже Y=0. Ссылки на структуры читаются и пишутся с форматом координат Leaf, с проверкой радиуса. |
| **Тики чанков** | Сохранённые тики блоков и жидкостей попадают в очереди мира, выполняются по времени и приоритету, сохраняют оставшиеся задержки при выгрузке. При ошибке сохранения кэш удерживает чанк и очереди. Запрос стадии различает отсутствующий чанк, сохранённый чанк с незавершённой генерацией и повреждённую запись. |
| **StarLight в кэше** | `ServerChunkCache` восстанавливает или рассчитывает свет перед активацией тиков. Проверены распространение света через границу чанков, удаление источника и сохранение результата в Anvil. |
| **Gamerules, коллизии и граница мира** | Значения и NBT round-trip gamerules, коллизии в пустом мире, проверка границ и их анимация. |
| **Лаунчер** | Сборка `leaf-runner`, выбор JAR и проверка параметров JAR- и dev-режимов. |

| Подсистема | Состояние |

| **`network/protocol`** | Есть регистрации фаз handshake, status, ping, cookie, common, login, configuration и game. В [GameProtocols](crates/leaf-core/src/network/protocol/game/game_protocols.rs) 66 регистраций client → server, 138 server → client и отдельный разделитель server → client bundle. Есть инфраструктура `ProtocolInfo`, dispatch и бандлов, чат-компоненты, стили и события. |
| **`core/`, `resources/`, `util/` и JOML** | Перенесены используемые ядром типы позиций, направлений, `Identifier`, `ResourceKey`, `TagKey`, `Holder`, реестры, `mth`, битовое хранилище, векторы, матрицы и кватернионы. |

Сохранение `ItemStack` и экипировки использует NBT-патч с типизированными значениями и отметками удаления. Сохраняются вложенные стопки в контейнерах, мешках, заряженных арбалетах и остатках от использования. Добавлены NBT-кодеки для еды, задержки использования, эффектов использования, дальности атаки, оружия, анимации взмаха и цвета. Часть сложных данных, включая данные карт, замков и лута, хранится как NBT. |
| **Мир, чанки и освещение** | Есть интерфейсы `Level`, `LevelAccessor`, `LevelReader`, настройки измерения, погода, время, `TickRateManager` и `ServerChunkCache`. Модуль StarLight содержит блочный и небесный слои, SWMR-нибблы, проверку границ и обновление света после изменения блока. |
| **Генерация рельефа** | Есть шумовые и плотностные функции, параметры климата, биомы, карверы и размещение features. `ChunkGenerationTask` планирует стадии по зависимостям и повторяет незавершённые стадии после ошибки. `ServerChunkCache::load_through` выполняет загрузку до нужной стадии. `generate_through` запускает стадии переданного генератора, ограничивает область записи и собирает изменения до успешного завершения стадии. StarLight и переход `ProtoChunk` → `LevelChunk` выполняются в кэше. |
| **Структуры** | Есть шаблоны, размещение, pools, Jigsaw, `StructureStart`, части, индексы и обработка legacy-данных. Перенесены реализации шахт, монументов, особняков, крепостей Нижнего мира и stronghold, а также ряда малых и шаблонных структур. В формате Leaf читаются и записываются части клада, пустынной пирамиды, храма в джунглях, хижины ведьмы и все четыре типа частей шахты. |
| **Коллизии, взрывы и спавн** | Есть `VoxelShape`, `WorldBorder`, `BlockCollisions`, модели и алгоритмы взрывов, `BaseSpawner` и `NaturalSpawner`. Часть игровых операций проходит через хуки уровня и сущностей. |
| **Сущности и AI** | Есть `Entity`, `LivingEntity`, `Mob`, атрибуты, урон и эффекты. Реализованы модули goals, Brain, POI, навигации и pathfinding, в том числе поведение деревенских жителей. |

### 🔴 Осталось

1. **World/level runtime** — подключить кэш, освещение, тики блоков, жидкостей и блок-сущностей к игровому циклу `ServerLevel`. Подключить конкретный генератор рельефа и контента, реестры структур и загрузку всех типов частей.
2. **Сеть** — связать обработчики игровой сессии с игроком и миром, проверить подключение клиента и обмен игровыми пакетами.
3. **Сущности и игроки** — подключить менеджер сущностей, конкретные сущности и AI, инвентарь игрока и игровые взаимодействия.
4. **Команды** — перенести оставшиеся аргументы, включая селекторы сущностей, и встроенные команды. Связать выполнение и подсказки с источником команд `ServerLevel` и игровой сессией.
5. **Data components** — загрузить каталог ванильных предметов с их прототипами, довести игровые модели, persistent-кодеки и разрешение именованных наборов holder.
6. **Plugin API** — перенести Bukkit/Paper API и проверить совместимость с плагинами. Rust-модуль `plugin` пока пуст.
7. **Нативные методы JVM** — внешняя зависимость проекта. В локальных логах зафиксированы файловые исключения при запуске.
8. **Полный прогон** — подтвердить запуск `nogui` до `Done` и подключение клиента на Rust-JVM.

### 🏃 Текущий запуск

`leaf-native` поднимает локальный TCP-сервер с плоским миром. Вход и загрузка мира проверены обычным клиентом Minecraft 1.21.11. TCP-тест дополнительно проверяет подгрузку соседних чанков при перемещении.

`leaf-runner` запускает Java-сборку Leaf на Rust-JVM. В предыдущих локальных прогонах сервер доходил до `PaperBootstrap` и инициализации конфигурации Paper. В dev-режиме зафиксирована ошибка `Invalid TypeToken; must specify type parameters`. Запуск до `Done` пока не подтверждён.

## Участие в разработке

Сверяйте поведение Rust-кода с Java-референсом Leaf 1.21.11. Для изменений форматов и алгоритмов добавляйте целевые проверки. Перед Pull Request запустите тесты Rust workspace и обновите затронутые статусы в README. Деревья Java и Rust-JVM, сборки и рабочие данные остаются локальными.
